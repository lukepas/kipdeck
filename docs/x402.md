# Paid tasks over x402

Back to the [README](../README.md).

Part of the Proof of Merge fork of [agent-office](https://github.com/AgentSystemLabs/agent-office) (MIT, by webdevcody / AgentSystemLabs). Testnets only: Base Sepolia, and Solana devnet. Off unless the office is started with `--x402`.

Someone outside the office, a person with a shell or another agent, pays a small amount of test USDC to put one task on a floor's queue: an issue, or a prompt, for a repository the office opted in. The office answers with HTTP 402 and what it wants, the payer signs, a facilitator verifies and settles the payment, and the task goes on the queue held. Nothing starts until an office admin reads it and approves it.

## Turning it on

```sh
agent-office --x402 \
  --x402-pay-to 0x<the office's Base Sepolia address> \
  --x402-repos acme/app,acme/docs \
  [--x402-price 0.10] [--x402-pay-to-solana <devnet address>] [--x402-asset 0x<TestUSDC>]
```

| Switch | What it does |
| --- | --- |
| `--x402` | Takes paid tasks (env `AGENT_OFFICE_X402=1`) |
| `--x402-pay-to` | The office's Base Sepolia wallet. Only its public address is given; the office holds no key |
| `--x402-repos` | The repositories a paid task may be for. Each must be open as a floor |
| `--x402-price` | Per task, in test USDC (default 0.10) |
| `--x402-pay-to-solana` | Also take devnet USDC, paid to this address. Offered once the facilitator names its devnet fee payer |
| `--x402-facilitator` | Who verifies and settles (default `https://x402.org/facilitator`, which settles testnets only) |
| `--x402-asset` | A test token standing in for Circle's Base Sepolia USDC (`onchain/x402/scripts/deploy-test-usdc.ts`) |

Each has an `AGENT_OFFICE_X402_*` environment twin. A bad value stops the office at start.

## The routes

All public (the payer has no session) and after the host check, like every route:

| Route | What it answers |
| --- | --- |
| `GET /api/x402` | The offer: price, networks, asset, payee, repositories, the task URL, the prompt cap |
| `POST /api/x402/task` | `{"repo": "owner/name", "issue": 12}` or `{"repo": ..., "prompt": "..."}`, optionally `"harness"`. Without a payment: `402` with `PAYMENT-REQUIRED`. With one in `PAYMENT-SIGNATURE` (or v1's `X-PAYMENT`): `202 {"taskId", "status": "held", "statusUrl"}` with `PAYMENT-RESPONSE` and `X-PAYMENT-RESPONSE` |
| `GET /api/x402/tasks/<id>?key=...` | Where a paid task stands. The key is in the `statusUrl` the payer was given |

Before anyone pays, the office checks the repository is on the list and open as a floor, that the request is an issue or a prompt (at most 4000 characters), that the harness is one the floor runs, that the prompt passes the office's own checks (never a fork's pull request to check out and run), and that the issue isn't on the queue already. Each client address gets 20 tries a minute.

With a payment, the office checks it is for exactly what it asked (scheme, network, token, payee, amount, the EIP-3009 time window), then has the facilitator verify it, puts the task on the queue held with no transaction yet (so it can't start unpaid), writes the payment into its ledger, has the facilitator settle it, and records the transaction. If the facilitator says the settlement failed, the task comes off again and the ledger entry goes. If it doesn't answer (a timeout), or the office stops while it settles, nobody knows whether the payment went through, and the payer's authorization may be spent: the task stays held, marked *settlement unknown* on the queue and in the payer's status link. An admin looks for the payer's transfer on the explorer, then records its transaction (**Record settlement**), after which the task can be approved, or turns the task down. A paid task that is run again goes back to an admin, held, as if it were new. The same payment sent twice with the same request gets the same task back; with another request it is refused.

The facilitator is reached through the office's network guard (`src/server/netguard.ts`): its own host only, over https, no redirects, a capped answer. A facilitator on `http://127.0.0.1` is reached only when its URL names that address, for local test runs.

## What the worker gets

The payer's words are framed as an untrusted outsider's request, between markers they can't close, with the instruction to do only the work on that repository and nothing that would reveal secrets, read files outside the repository, touch credentials or reach other hosts. An issue task names the issue and says the same of its text.

## Approving, turning down, refunding

Held paid tasks show on the 📋 queue board with what was paid and a link to the payment. Only an admin can act on them, and the office checks that on its side:

- **Approve** (`queue.approve`): the task joins the queue. Its worker runs on the approver's sign-ins, so the approver needs one for its agent.
- **Turn down** (`queue.reject`): the task is done, marked turned down, and a refund is owed.
- **Record refund** (`queue.refunded`): a paid task that was turned down is refunded by hand, from the office's wallet, to the payer's address. The admin then records that transaction (it must look like one on the network it was paid on), and the timeline shows the refund with its explorer link. A turned-down task stays on the board until its refund is recorded.

Each step goes on the floor's timeline once: `task-paid` (with the payment's link), `task-approved`, `task-rejected`, `task-refunded` (with the refund's link).

## Paying from a shell or an agent

`onchain/x402` is the payer: a CLI and an MCP server (`hire_worker`, `task_status`) that sign with `@x402/evm` from a key file. See [its README](../onchain/x402/README.md).

```sh
cd onchain/x402 && npm install
export X402_PAYER_KEY_FILE=$HOME/.config/agent-office-chain/base-payer.json
npx tsx src/cli.ts pay https://office.example --repo acme/app --issue 42 --max 0.10
```

## Testnet funds

The payer needs Base Sepolia test USDC from [faucet.circle.com](https://faucet.circle.com), a browser faucet. When that can't be had, `onchain/x402/scripts/deploy-test-usdc.ts` deploys TestUSDC (6 decimals, USDC's EIP-712 domain, EIP-3009) to Base Sepolia, mints some to the payer, and the office takes it with `--x402-asset`. `onchain/attest/scripts/deploy-sepolia.sh --test-usdc` does that for you.

## Code

| Path | What it does |
| --- | --- |
| `src/server/x402/protocol.ts` | Networks, headers, requirements, the office's own checks |
| `src/server/x402/facilitator.ts` | `/verify`, `/settle`, `/supported` through the network guard |
| `src/server/x402/gateway.ts` | The routes' logic, the request checks, the payment ledger (`x402.json`) |
| `src/server/http/routes/x402.ts` | The public routes |
| `src/server/queue.ts`, `ws/handlers/queue.ts` | Held tasks, approve, turn down, refund |
| `src/client/ui/paid-task.ts` | The queue board's paid task row |

Tests: `tests/x402.test.ts` (the 402 flow with a stand-in facilitator, the checks before payment, admin-only approval, refunds, the timeline), and `onchain/x402/test/office.test.ts` (a viem-signed payment against this gateway, verified and settled by the package's mock facilitator, which recovers the signature).
